# 밑빠진 독상 (dokseong)

함께하는 시민행동 **밑빠진 독상** 사이트. 2000년 제1회부터 2025년 제40회까지 이어온
예산낭비 감시 활동을, 제41회부터는 **분기마다** 시민 제보와 투표로 함께 만들어갑니다.

> **운영 구조 변경(2026-08-24):** 실제 제보는 캠페이너스 입력폼, 서명은
> 도너스, 투표는 12월에 다시 정합니다. 이 저장소의 D1/R2/API 구현은 과거
> 설계이며 새 운영에는 사용하지 않습니다. 현재 상태와 남은 작업은
> [OPERATIONS.md](OPERATIONS.md)를 기준으로 확인하세요.

```
제보 접수 → 후보 선정 → 시민 투표 → 수상 발표 → 캠페인 서명 → (다음 분기)
```

## 구조

```
dokseong/
├── public/
│   ├── index.html          # 페이지 전체 (HTML + CSS + JS 한 파일)
│   ├── privacy.html        # 개인정보 처리방침 (초안 — 채워야 할 곳이 있음)
│   └── data/
│       ├── map-sido.json       # 시도 16개 (SVG 경로, 전남광주 통합 반영)
│       ├── map-sigungu/        # 기초자치단체 229개 (아직 화면에 안 씀)
│       └── awards.json         # 역대 수상 40건 + 지역 코드
├── functions/
│   └── api/
│       ├── report.js       # POST /api/report  — 시민 제보 접수
│       └── regions.js      # GET  /api/regions — 지역별 제보 건수
├── tools/                  # 지도·수상 데이터 만드는 스크립트
├── schema.sql              # D1 테이블 정의
└── wrangler.toml           # Cloudflare Pages 설정 · 회차 번호
```

**Cloudflare Pages + Functions**를 씁니다. 빌드 단계가 없습니다 —
`public/`은 그대로 서비스되고, `functions/` 안의 파일 하나가 그대로 API 주소가 됩니다
(`functions/api/report.js` → `/api/report`).

> 예산게임(budget-mbti)의 Vite + Worker 구성은 일부러 따라가지 않았습니다.
> 로컬에서 DB 붙이는 것만도 손이 많이 가는 구조라, 여기서는 단순한 쪽을 골랐습니다.

## CSS 범위 규칙 (중요)

나중에 이 페이지를 **캠페이너스 홈페이지 안에 통째로 붙여넣을** 예정입니다.
그래서 모든 CSS 규칙이 `#dok` 안에 갇혀 있고, 클래스는 전부 `dok-` 로 시작합니다.

- ❌ `.card { ... }`, `body { ... }`, `* { ... }`
- ✅ `#dok .dok-card { ... }`

전역 선택자를 쓰면 붙여넣는 순간 홈페이지 전체 레이아웃이 깨집니다.
전역 규칙은 `html { scroll-behavior }` 하나뿐이고, 이식할 때 그 줄만 지우면 됩니다.
이식 단위는 `public/index.html` 안의 `<div id="dok">` … `</div>` 통째입니다.

## 예산감시 사업 내용 고치는 법

분기마다 손대는 곳은 `public/index.html` 안 두 군데입니다. **코드는 건드리지 않습니다.**

1. **목록** — `<script type="application/json" id="dok-campaign-data">`
   카드에 보이는 제목·요약·기간·상태(`ongoing`/`closed`)·결과 한 줄.
2. **상세 내용** — `<div id="dok-camp-bodies">` 안의 `<article data-camp="아이디">`
   카드를 눌렀을 때 열리는 보고서 본문. 그냥 HTML이라 `<h4>`, `<p>`, `<a>`를
   평소처럼 쓰면 됩니다. JSON 안에 긴 글을 넣으면 줄바꿈·따옴표 때문에
   쓰기 어려워서 일부러 나눴습니다.

두 곳의 **`id`와 `data-camp` 값이 같아야** 연결됩니다.
`<article>`이 없으면 "아직 정리된 내용이 없습니다"가 뜨고, 오류가 나지는 않습니다.

- 진행 중인 사업 → 무엇이 문제인지, 지금까지 확인한 것, 앞으로 할 일
- 종료된 사업 → 무엇이 문제였는지, 무엇이 남았는지 (+ `outcome` 한 줄이 강조돼 표시됨)

## 이야기 채우는 법

히스토리 칸에는 원래 역대 수상 4건이 카드로 있었지만, 같은 목록이 **지도**와
**전체 수상 표**에 이미 나와서 뺐습니다. 그 자리는 상을 만들어 온 사람들의
글로 씁니다. 활동가 연재 글을 먼저 넣고, 후원자·회원 이야기는 나중에 붙입니다.

**글이 한 편도 없으면 이 칸은 화면에 나오지 않습니다.** 현재는 채연하 활동가의
첫 글 한 편이 들어가 있습니다.

고칠 곳은 `public/index.html` 안 두 군데입니다. **코드는 건드리지 않습니다.**

### 1. 목록 — `<script type="application/json" id="dok-story-data">`

```json
[
  {
    "id": "2026-08-yeongwol",
    "title": "영월에 다녀왔습니다",
    "author": "홍길동",
    "role": "함께하는 시민행동 예산감시팀",
    "date": "2026. 8",
    "excerpt": "카드에 보이는 두세 줄. 전문에서 그대로 따와도 됩니다.",
    "link": ""
  }
]
```

**적은 순서대로 나옵니다.** 새 글은 맨 위에 넣으세요.
`role`·`link`는 비워도 됩니다.

### 2. 본문 — `<div id="dok-story-bodies">` 안

```html
<article data-story="2026-08-yeongwol">
  <p>첫 문단.</p>
  <p>둘째 문단. <a href="...">링크</a>도 됩니다.</p>
</article>
```

목록의 `id`와 `data-story` 값이 **같아야** 이어집니다.

| 넣은 것 | 카드에 생기는 것 |
|---|---|
| 본문 `<article>` | **이어서 읽기** — 카드 안에서 펼쳐집니다 |
| 본문 없이 `link`만 | **원문 보기** — 새 창으로 열립니다 |
| 둘 다 없음 | 발췌까지만 |

### 소제목 문구

카드 위 두 줄("상을 주는 사람들" / "밑빠진 독상을 만들어 온 활동가들의 글입니다")은
`index.html`에 그냥 적혀 있습니다. 마음에 안 들면 그대로 고쳐 쓰면 됩니다.

### 후원자·회원 이야기를 붙일 때

같은 목록에 그냥 추가하면 활동가 글과 같은 카드로 나옵니다. 글이 짧아서
카드 크기를 달리하고 싶다면, 항목에 `"kind": "supporter"` 같은 칸을 만들고
`.dok-story-card` 에 클래스를 하나 더 붙이는 정도로 충분합니다.
**미리 만들어 두지는 않았습니다** — 쓰지 않는 화면에 기능이 붙어 있으면
나중에 이게 되는 기능인지 아닌지 알 수 없게 되기 때문입니다.

## 지도

시도 단위까지만 그립니다. 지도를 누르거나, 아래 **지역 칩**을 눌러 지역을 고릅니다.
칩이 따로 있는 이유는 모바일(334px)에서 인천·대전·세종 같은 작은 시도를
손가락으로 누를 수 없기 때문입니다. 지도는 보는 것, 칩은 누르는 것입니다.

기초자치단체(시군구) 드릴다운은 데이터가 이미 `public/data/map-sigungu/`에
준비돼 있고, 행정구역 변경분을 반영한 뒤에 붙일 예정입니다.

### 전남광주통합특별시

광주광역시와 전라남도가 통합되어, 지도에서 두 지역을 **하나로 합쳤습니다.**

- 코드는 전남의 `36`을 그대로 씁니다. 이미 D1에 쌓인 제보의 `sido` 값과
  API의 두 자리 검사(`/^\d{2}$/`)를 그대로 통과하기 때문입니다.
- 광주 코드 `24`는 지도에서 사라졌습니다. **광주로 접수된 제보가 있다면**
  아래 SQL로 옮겨야 지도 집계에 잡힙니다.

```bash
npx wrangler d1 execute dokseong --remote \
  --file=migrations/2026-08-24-gwangju-to-jeonnam.sql
```

- 전남 도형 안에 광주 자리가 구멍으로 뚫려 있던 것을 **구멍째 지웠습니다.**
  광주 경로를 덧대는 방법도 있지만, 그러면 합쳐 놓고도 경계선이 그대로 남습니다.
- `public/data/map-sigungu/24.json`(광주 5개 자치구)과 `36.json`은 **아직 그대로**입니다.
  시군구 드릴다운을 붙일 때 두 파일을 합쳐야 합니다. 그때 `report.js`의
  `data.sido = data.sigungu.slice(0, 2)`도 손봐야 합니다 — 광주 시군구 코드는
  `24`로 시작해서, 그대로 두면 없어진 시도 코드가 다시 생깁니다.

> 지도 원본(통계청 2018)에는 이후 바뀐 이름들이 반영돼 있지 않습니다.
> 강원도·전라북도 등이 화면에 옛 이름으로 나옵니다. 확인되면 함께 고쳐 주세요.

지도 데이터를 다시 만드는 방법은 [tools/README.md](tools/README.md)를 보세요.

## 회차 관리

분기마다 바뀌는 값은 코드가 아니라 `wrangler.toml`의 `[vars]`에 있습니다.

| 변수 | 뜻 |
|---|---|
| `CURRENT_ROUND` | 지금 진행 중인 회차 (제41회 = `"41"`) |
| `REPORT_OPEN` | `"0"`으로 두면 제보 접수가 닫힘 |
| `REPORT_DEADLINE` | 이번 차수 마감일. 제보는 상시 받되 이 날까지를 한 묶음으로 봄 |
| `REPORT_DEADLINE_LABEL` | 화면에 뜨는 이름 (예: 하반기 1차 제보 마감) |

> 마감 날짜는 `public/index.html` 의 `#dok-deadline` 에도 박혀 있습니다.
> 차수를 넘길 때 **두 곳을 같이** 고쳐야 합니다.

## 공개 안전장치 (2026-09-02)

이 사이트는 이미 밖에서 열립니다(`dokseong-action.bada523082.chatgpt.site`).
그래서 **확인 안 된 값**과 **갈 곳 없는 개인정보 입력**을 화면에 두면 안 됩니다.
`public/index.html` 스크립트 맨 위에 스위치 두 개를 뒀습니다. **파일을 뜯어고치지 말고
그 두 곳만 바꾸세요.**

### `DOK_SHOW_SAMPLE` (지금 `false`)

예시(더미) 내용을 화면에 낼지 정합니다. 실제 값으로 갈아 끼운 뒤 `true` 로 바꾸세요.
`false` 인 지금 감춰지는 것 —

| 감춘 것 | 어디 |
|---|---|
| 예산감시 사업 4건(전부 `(예시)`)과 상세 보고서 | `#dok-campaign-data` |
| 제41회 투표 후보 5건 | `#dok-vote-fold` 통째 |
| '이렇게 제보가 쓰입니다' 예시 제보 2건 | `#dok-sample-data` |
| 첫 화면 지표 **1,000억 원** | `.dok-stat-item.is-lead` |

`40회`·`26년` 두 지표는 실제 값이라 그대로 둡니다.
사업 목록 자리에는 '정리하고 있습니다' 안내가 뜹니다(빈 화면이 되지 않습니다).

### `DOK_INTAKE` (지금 셋 다 `disabled`)

폼이 받은 것을 어디로 보낼지 정합니다.

- `'disabled'` — **보내지 않습니다.** 칸과 버튼이 잠기고 안내만 뜹니다.
- `'link'` — 우리 폼 대신 `url` 의 바깥 접수처로 보냅니다(캠페이너스 입력폼 · 도너스).

```js
const DOK_INTAKE = {
  report:  { mode: 'disabled', url: '' },   // 예산낭비 제보 → 캠페이너스 입력폼
  join:    { mode: 'disabled', url: '' },   // 감시 참여·서명 → 도너스
  regions: { mode: 'disabled', url: '' },   // 지역별 제보 건수 집계
};
```

**빗장을 둘 두었습니다.** 화면에서 칸을 잠그는 것 하나, 제출 처리 맨 앞에서 되돌리는 것
하나입니다. 개발자도구로 `disabled` 를 풀어도 이름·이메일·전화번호·제보 사진이
바깥으로 나가지 않습니다.

**하드코딩돼 있던 `/api/report` · `/api/join` · `/api/regions` 를 모두 걷어냈습니다.**
2026-08-24 운영 구조 변경(`OPERATIONS.md`)으로 그 주소들은 쓰지 않습니다 — 부르면
실패하거나 아무 데도 저장되지 않았습니다. 이제 주소는 `DOK_INTAKE` 한 곳에만 있습니다.

### 접수처를 붙이려면 받아야 하는 값

`OPERATIONS.md` 2·3장에 정리돼 있습니다.

- **제보** — 캠페이너스 입력폼 주소. 사진은 `사진 1~3` 세 항목(전부 선택)으로.
- **서명** — 도너스 Formkey · 참여 채널 코드 · 참여 분류 코드 · 캠페인 제목/태그 규칙 ·
  동의 문구 버전과 동의 시각을 담을 사용자정의필드.
  ⚠️ 일반 API Key 를 브라우저에 넣지 말 것. Forms API 의 Formkey 만 씁니다.

### 개인정보 — 아직 사람이 확인해야 하는 것

`public/privacy.html` 은 2026-09-01 에 시민행동이 실제로 쓰는 방침 전문으로 갈았습니다.
**빈칸은 없습니다**(위 '이어서 할 일'의 "16곳 채우기"는 지난 이야기입니다).
대신 남은 어긋남이 있습니다 —

1. 그 방침은 **회원·후원자 문서**라 제보·제보 사진·서명·해외 클라우드 보관을 다루지 않습니다.
2. 별첨 **'캠페인 소식 및 후원 정보 수신 동의'** 가 빠졌습니다(폼 안에 같은 글이 따로
   있어 화면은 안 깨집니다).
3. 회신 이메일이 추첨 당첨 안내에도 쓰이는데 방침의 이용 목적에는 추첨이 없습니다.
4. 방침 2번의 제보 항목은 "필수: 사업명" 인데 실제 폼에는 사업명 칸이 없습니다
   (사진 첨부로 대체했습니다).
