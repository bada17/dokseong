> 작업 규칙은 **`AGENTS.md`** 에 있습니다. Claude 와 GPT 는 폴더를 열 때 그 파일을 자동으로 읽습니다.
> 기록은 이 `README.md` 한 곳에만 남기고, 지나간 것은 딱지를 붙이지 말고 지웁니다.


함께하는 시민행동 **밑빠진 독상** 사이트. 2000년 제1회부터 2025년 제40회까지 이어온

> 캠페이너스 홈페이지 안으로 **이식하지 않습니다.** 예전 문서 곳곳에 "나중에

## 별도 페이지로 갑니다 (2026-09-03 결정)

캠페이너스 안으로 옮기지 않고, 이 저장소가 배포하는 **독립된 사이트로 계속** 운영합니다.
그래서 아래 것들이 **임시가 아니라 최종 형태**입니다.

| | 이식을 전제했을 때 | 별도 페이지로 갈 때 (지금) |
|---|---|---|
| 바깥 파일 읽기 (`data/*.json`) | 상대주소가 404 나서 절대주소가 필요 | **상대주소 그대로** 써도 됩니다 |
| 제보 접수 | 이식하면 캠페이너스 입력폼 위젯을 그 자리에 심는다 | **새 탭으로 여는 링크가 끝까지 갑니다** |
| 우리 제보 팝업 | 이식 전까지만 쓰는 임시 화면 | **접수처가 바깥이면 쓰이지 않습니다** — 아래 참고 |
| `#dok` CSS 가두기 | 홈페이지를 안 깨뜨리려고 | 이유는 없어졌지만 **그대로 지킵니다** |

⚠️ **정하지 않은 것 하나** — 접수를 캠페이너스 입력폼(`mode: 'link'`)으로 넘기면
`#dok-report-form-modal` 의 우리 제보 폼은 화면에서 안 쓰이게 됩니다.
사진 미리보기·자동 축소·지역 자동 채우기가 거기 붙어 있습니다.
**쓰지 않을 화면을 남겨 두면 다음 사람이 되는 기능인지 아닌지 알 수 없게 됩니다.**
접수처를 붙이는 날 지울지 남길지 정하세요.

## CSS 범위 규칙 (중요)

모든 CSS 규칙이 `#dok` 안에 갇혀 있고, 클래스는 전부 `dok-` 로 시작합니다.

- ❌ `.card { ... }`, `body { ... }`, `* { ... }`
- ✅ `#dok .dok-card { ... }`

> **이 규칙은 원래 캠페이너스 이식을 위한 것이었습니다.**
> 2026-09-03 에 **이식하지 않기로** 정했으므로 그 이유는 사라졌습니다.
> 그래도 규칙은 **그대로 지킵니다** — 이미 4,000줄이 이 방식으로 쓰여 있고,
> 지금 와서 푸는 것은 얻는 것 없이 위험만 큽니다. 이 페이지에 새 코드를 더할 때도
> 같은 방식으로 쓰세요.

`public/index.html` 안의 주석에 남아 있는 `캠페이너스 이식 단위` 표시도
같은 이유로 지우지 않았습니다. **읽을 때 이식 계획으로 오해하지 마세요.**

## 예산감시 사업 내용 고치는 법

> ⚠️ **2026-09-03 에 목록이 바깥 파일로 나갔습니다.** `public/data/campaigns.json` 이
> 있으면 **그것이 이깁니다** — `index.html` 안의 `#dok-campaign-data` 를 아무리 고쳐도
> 화면은 안 바뀝니다(`setCampaigns()` 가 나중에 덮어씁니다). 옛 안내를 믿지 마세요.

분기마다 손대는 곳은 **두 군데**입니다. **코드는 건드리지 않습니다.**

1. **목록** — `public/data/campaigns.json` ← **여기가 진짜입니다**
   카드에 보이는 제목·요약·기간·상태(`ongoing`/`closed`)·결과 한 줄.
   (`index.html` 의 `#dok-campaign-data` 는 이 파일을 못 읽었을 때의 대비책입니다)
2. **상세 내용** — 둘 중 하나로 씁니다.
   - `campaigns.json` 의 `"body"`: `[["h","소제목"],["p","문단"],["img","주소","설명"]]`
   - 또는 `index.html` 의 `<div id="dok-camp-bodies">` 안 `<article data-camp="아이디">`
     (그냥 HTML 이라 긴 글을 쓰기 편합니다. **`body` 가 비어 있을 때만** 쓰입니다)

목록의 **`id` 와 `data-camp` 값이 같아야** 연결됩니다.
둘 다 없으면 "아직 정리된 내용이 없습니다"가 뜨고, 오류가 나지는 않습니다.

⚠️ **`data-camp` 만 있고 목록에 없는 본문은 어디로도 안 열립니다.**
   지금 `teukhwalbi` · `jomulmul` · `gyeongin` 셋이 그 상태입니다(전부 예시 글).

- 진행 중인 사업 → 무엇이 문제인지, 지금까지 확인한 것, 앞으로 할 일
- 종료된 사업 → 무엇이 문제였는지, 무엇이 남았는지 (+ `outcome` 한 줄이 강조돼 표시됨)

⚠️ **상세 내용에서 `#` 은 소제목입니다.** 모든 줄 앞에 `#` 을 붙이면 글 전체가
파란 소제목이 됩니다(2026-09-10 에 실제로 그랬습니다 — `camp-3` 의 15줄이 전부
소제목이었습니다). 문단은 그냥 쓰고 **빈 줄로 나누세요.**

### 사업 하나로 바로 가는 주소 (2026-09-10)

`https://dok.action.or.kr/#camp-<사업 id>` 로 들어오면 **그 사업 팝업이 열린 채로**
뜹니다. 종료된 사업이면 탭도 '종료'로 옮겨 둡니다. 닫으면 주소가 조용히 지워집니다.

시민행동 홈 첫 화면의 캠페인 칸이 이 주소를 씁니다 — '2026 하반기 밑빠진 독상' 줄
밑에 **진행 중인 감시사업**이 하위 줄로 붙고, 누르면 여기로 옵니다

## 이야기 채우는 법

히스토리 칸에는 원래 역대 수상 4건이 카드로 있었지만, 같은 목록이 **지도**와
**전체 수상 표**에 이미 나와서 뺐습니다. 그 자리는 상을 만들어 온 사람들의
글로 씁니다. 활동가 연재 글을 먼저 넣고, 후원자·회원 이야기는 나중에 붙입니다.

**글이 한 편도 없으면 이 칸은 화면에 나오지 않습니다.**

### ★ 2026-09-10 — 글은 이제 구글 시트와 구글 문서로 올립니다

앞으로 글이 여러 편 올라갈 자리라, 한 편 올릴 때마다 이 저장소를 고치고 배포하는
방식을 그만뒀습니다. **시민참여 상담소의 '전문위원의 글'과 같은 방식**입니다.

```
시트   접수 시트의 `활동가의 글` 탭 — 목록 한 줄 (제목·필자·소속·날짜·문서 주소·공개·한 줄 소개)
문서   그 줄이 가리키는 구글 문서 — 본문 (사진·표·소제목·목록·굵게·링크 다 됩니다)
```

1. 활동가가 **구글 문서**에 글을 씁니다. 글 한 편 = 문서 하나입니다.
   (한 문서에 탭을 나눠 여러 편 넣지 마세요 — 코드가 첫 탭만 읽습니다.)
2. 담당자가 시트 `활동가의 글` 탭에 **한 줄** 적습니다. 문서 주소는 그대로 붙여넣으면 됩니다.
3. `공개` 칸을 **공개**로 바꾸면 그때 화면에 나옵니다. `숨김`이면 안 나갑니다.
4. 화면에는 늦어도 1분 안에 반영됩니다(목록을 1분 재워 둡니다).

**순서는 시트에 적힌 순서 그대로**입니다. 새 글을 위에 두려면 시트에서 줄을 위로 옮기세요.
본문은 방문자가 **'글 읽기'를 눌렀을 때** 받아 옵니다(열 편을 미리 받으면 무겁습니다).

**글은 팝업으로 펴집니다**(2026-09-10). 카드 안에서 펼치면 글이 쌓일수록 목록이
한없이 길어져서, 상담소와 같은 방식으로 바꿨습니다. 목록은 그대로 두고 그 위에
창을 덮으므로 닫으면 보던 자리에 그대로 남습니다.
주소에 `#story-<id>` 가 남아서 **글 하나로 링크를 걸 수 있습니다** — 뉴스레터에서
그 주소로 보내면 그 글이 열린 채로 들어옵니다. 뒤로가기로 닫힙니다.

⚠️ 스크립트를 고쳤으면 **새 버전으로 다시 배포**해야 합니다 — `intake/README.md`.
⚠️ 시트에 새 탭을 만드는 것은 `setUp()` 입니다. 한 번 실행하면 생깁니다.

### 시트가 답하지 않을 때 — `public/index.html` 의 대비책

아래 두 군데는 **지우지 마세요.** 배포 전이거나 스크립트가 멎었을 때 화면에 남는
글입니다(지금은 채연하 활동가의 첫 글). **시트에서 한 편이라도 오면 화면은 통째로
시트 것으로 바뀝니다** — 그러니 같은 글을 시트에 올렸으면 여기서는 지우세요.

고칠 곳은 `public/index.html` 안 두 군데입니다. **코드는 건드리지 않습니다.**

### 1. 목록 — `<script type="application/json" id="dok-story-data">`

```json
[
  {
    "id": "2026-08-yeongwol",
    "title": "영월에 다녀왔습니다",
    "author": "홍길동",
    "role": "함께하는 시민행동 예산감시팀",
    "date": "2026. 8",
    "excerpt": "카드에 보이는 두세 줄. 전문에서 그대로 따와도 됩니다.",
    "link": ""
  }
]
```

**적은 순서대로 나옵니다.** 새 글은 맨 위에 넣으세요.
`role`·`link`는 비워도 됩니다.

### 2. 본문 — `<div id="dok-story-bodies">` 안

```html
<article data-story="2026-08-yeongwol">
  <p>첫 문단.</p>
  <p>둘째 문단. <a href="...">링크</a>도 됩니다.</p>
</article>
```

목록의 `id`와 `data-story` 값이 **같아야** 이어집니다.

| 넣은 것 | 카드에 생기는 것 |
|---|---|
| 본문 `<article>` | **글 읽기** — 팝업으로 펴집니다 |
| 본문 없이 `link`만 | **원문 보기** — 새 창으로 열립니다 |
| 둘 다 없음 | 발췌까지만 |

### 소제목 문구

카드 위 두 줄("상을 주는 사람들" / "밑빠진 독상을 만들어 온 활동가들의 글입니다")은
`index.html`에 그냥 적혀 있습니다. 마음에 안 들면 그대로 고쳐 쓰면 됩니다.

### 후원자·회원 이야기를 붙일 때

같은 목록에 그냥 추가하면 활동가 글과 같은 카드로 나옵니다. 글이 짧아서
카드 크기를 달리하고 싶다면, 항목에 `"kind": "supporter"` 같은 칸을 만들고
`.dok-story-card` 에 클래스를 하나 더 붙이는 정도로 충분합니다.
**미리 만들어 두지는 않았습니다** — 쓰지 않는 화면에 기능이 붙어 있으면
나중에 이게 되는 기능인지 아닌지 알 수 없게 되기 때문입니다.

## 지도

시도 단위까지만 그립니다. 지도를 누르거나, 아래 **지역 칩**을 눌러 지역을 고릅니다.
칩이 따로 있는 이유는 모바일(334px)에서 인천·대전·세종 같은 작은 시도를
손가락으로 누를 수 없기 때문입니다. 지도는 보는 것, 칩은 누르는 것입니다.

기초자치단체(시군구) 드릴다운은 데이터가 이미 `public/data/map-sigungu/`에
준비돼 있고, 행정구역 변경분을 반영한 뒤에 붙일 예정입니다.

### 전남광주통합특별시

광주광역시와 전라남도가 통합되어, 지도에서 두 지역을 **하나로 합쳤습니다.**

- 코드는 전남의 `36`을 그대로 씁니다. 이미 D1에 쌓인 제보의 `sido` 값과
  API의 두 자리 검사(`/^\d{2}$/`)를 그대로 통과하기 때문입니다.
- 광주 코드 `24`는 지도에서 사라졌습니다. **광주로 접수된 제보가 있다면**
  아래 SQL로 옮겨야 지도 집계에 잡힙니다.

```bash
npx wrangler d1 execute dokseong --remote \
  --file=migrations/2026-08-24-gwangju-to-jeonnam.sql
```

- 전남 도형 안에 광주 자리가 구멍으로 뚫려 있던 것을 **구멍째 지웠습니다.**
  광주 경로를 덧대는 방법도 있지만, 그러면 합쳐 놓고도 경계선이 그대로 남습니다.
- `public/data/map-sigungu/24.json`(광주 5개 자치구)과 `36.json`은 **아직 그대로**입니다.
  시군구 드릴다운을 붙일 때 두 파일을 합쳐야 합니다. 그때 `report.js`의
  `data.sido = data.sigungu.slice(0, 2)`도 손봐야 합니다 — 광주 시군구 코드는
  `24`로 시작해서, 그대로 두면 없어진 시도 코드가 다시 생깁니다.

> 지도 원본(통계청 2018)에는 이후 바뀐 이름들이 반영돼 있지 않습니다.
> **2026-09-08 에 둘을 고쳤습니다** — `강원도` → `강원특별자치도`(2023-06-11),
> `전라북도` → `전북특별자치도`(2024-01-18).
>
> ⚠️ 이름을 고칠 때는 **네 곳을 같이** 고쳐야 합니다 —
> `public/data/map-sido.json` · `public/data/map-sigungu/<코드>.json` ·
> `intake/Code.gs` 의 `SIDO` · 그리고 `SIDO_CODE` 에 **옛 이름 별칭**.
> 별칭을 빼면 이름이 바뀌기 전에 들어온 제보가 오류 없이 지도에서 빠집니다.

지도 데이터를 다시 만드는 방법은 [tools/README.md](tools/README.md)를 보세요.

## 제보 검토하기 — 시트에서

**제보는 사람이 한 번 열어봐야 지도에 오릅니다.** 접수는 자동, 표시는 수동입니다.
아무도 검토하지 않으면 지도는 계속 0건입니다.

시트의 `제보` 탭을 열고 오른쪽 네 칸을 씁니다. `상태` 만 고르면 **누가 언제 봤는지는
저절로 적힙니다** — 손으로 적게 두면 아무도 안 적고, 그러면 넷이 같은 제보를 세 번 읽고
아무도 안 읽은 제보가 남습니다.

| 상태 | 뜻 | 지도 |
|---|---|---|
| `접수` | 아무도 안 봤음 | ❌ |
| `검토중` | 읽었고 이상 없음 | ✅ |
| `후보` | 이번 회차 후보로 | ✅ |
| `탈락` | 제보는 맞지만 안 다룸 | ❌ |
| `스팸` | 장난·광고 | ❌ |

여럿이 나눠 볼 때는 **필터 보기**(`상태 = 접수`)를 씁니다. 필터 '보기'는 나만 보는
것이라 남의 화면을 건드리지 않습니다. 회차별로 보려면 `회차 = 41` 로 거릅니다 —
**탭을 회차마다 나누지 않습니다.** 나누면 밀린 것을 한 곳에서 훑을 수가 없습니다.

자세한 것은 [`intake/README.md`](intake/README.md) 를 보세요.

⚠️ **관리자 웹페이지를 일부러 만들지 않았습니다.** 공개된 주소에 관리 화면을 두면
   비밀번호 하나로 제보자 정보 전체가 열리는 문이 인터넷에 생깁니다.
   시트는 구글 계정으로 들어가므로 그 문이 없습니다.

⚠️ **보관 기간이 지난 줄을 지우는 코드가 아직 없습니다.** 방침에는 회차 종료 후 1년이라
   적어 두었습니다 — 적어만 두고 안 지우면 사실상 영구 보관입니다.
   `tools/review.py` 에는 그 기능이 있었지만 D1 을 읽는 도구라 지금은 돌지 않습니다.

### `DOK_INTAKE`

폼이 받은 것을 어디로 보낼지 정합니다.

- `'disabled'` — **보내지 않습니다.** 칸과 버튼이 잠기고 안내만 뜹니다.
- `'sheet'` — **제보 전용.** 구글 Apps Script 웹앱으로 보냅니다(`intake/Code.gs`).
- `'link'` — 우리 폼 대신 `url` 의 바깥 접수처로 새 탭을 엽니다.
- `'donus'` — **서명 전용.** 우리 참여 팝업에서 도너스 Forms API 로 바로 씁니다.

```js
const DOK_SHEET_ENDPOINT = '';   // ← 구글 웹앱 /exec 주소. 비어 있으면 제보 폼이 잠깁니다

const DOK_INTAKE = {
  report:  { mode: 'sheet', url: DOK_SHEET_ENDPOINT },   // 제보 → 시트 + 드라이브
  join:    { mode: 'donus', url: '' },                   // 서명 → 도너스
  regions: { mode: 'sheet',                              // 지역별 제보 건수
             url: DOK_SHEET_ENDPOINT ? DOK_SHEET_ENDPOINT + '?action=regions' : '' },
};
```

**주소가 비면 잠깁니다.** 서명이 `formkey` 를 보는 것과 같은 짜임입니다 —
`'sheet'` 라고 적어 두고 주소를 안 넣은 상태를 '잠김' 으로 봅니다.
옛 `'api'` 모드(`functions/api/`)는 2026-09-04 에 안 쓰게 됐습니다.

**빗장을 둘 두었습니다.** 화면에서 칸을 잠그는 것 하나, 제출 처리 맨 앞에서 되돌리는 것
하나입니다. 개발자도구로 `disabled` 를 풀어도 이름·이메일·전화번호·제보 사진이
바깥으로 나가지 않습니다.

### 서명을 여는 법 (도너스, 2026-09-03)

`index.html` 의 `DOK_INTAKE.join.mode` 를 `'donus'` 로 바꾸고, 바로 아래 `DOK_DONUS`
에서 **`formkey` 와 `channel` 두 칸**을 채우면 열립니다. **둘 중 하나라도 비어 있으면
`'donus'` 라고 적어도 폼은 잠긴 채로 있습니다** — 빈 값으로 켜서 개인정보가 엉뚱한
데로 나가는 일을 막으려는 것입니다(`dokJoinReady()`).

| `DOK_DONUS` 칸 | 도너스 어디에서 | 필수 |
|---|---|---|
| `formkey` | 관리시스템에서 발급한 Formkey | 필수 |
| `channel` | 기초정보 > 활동채널 → 활동채널코드 | 필수 |
| `category` | 기초정보 > 활동분류 → 활동분류코드 | 선택 |
| `consentField` | 활동기록 사용자정의필드 `info1`~`info5` 중 하나 | 선택 |

보내는 것은 `POST https://cloud.donus.org/api/forms/v0/submit/interact/<formkey>` 하나이고,
`registerMember: true` 로 이메일(없으면 휴대폰)로 기존 구성원을 찾아 붙입니다.
활동유형은 `ENG`(참여), 활동명은 `[밑빠진 독상] <사업 제목>`, 태그는 `밑빠진 독상` + 사업 id,
UTM 5종은 도너스 이름(`utmSource` 등)으로 옮겨 담습니다.

- **CORS 는 확인했습니다** (2026-09-03). 도너스가 `access-control-allow-origin: *` 을
  주므로 어느 도메인에서 올려도 브라우저가 바로 POST 할 수 있습니다.
- **`updateOnMatch` 는 `false` 입니다.** 이미 도너스에 있는 사람이 서명해도 그 사람의
  이름·수신동의를 이 폼 값으로 덮어쓰지 않습니다. 공개된 폼에서 들어온 값이 기존
  후원회원 기록을 덮으면 되돌리기 어렵습니다(활동기록은 정상적으로 남습니다).

  **2026-09-03 에 실제로 시험해서 확인했습니다.** 도너스 도움말에는 "이메일 또는
  휴대전화번호가 중복되는 구성원이 있으면 해당 구성원의 수신동의 값이 변경됩니다"
  라고 적혀 있어 위험해 보였는데, `updateOnMatch:false` 면 수신동의도 안 바뀝니다.
  시험 방법 — 시험 구성원을 한 건 넣고(전화·우편 자동으로 '거부'), 사람이 그 둘을
  '동의' 로 바꾼 뒤, 같은 이메일로 한 번 더 제출했더니 **'동의' 가 그대로 남았습니다.**
  활동기록만 2건으로 쌓였습니다. `updateOnMatch` 를 `true` 로 바꾸면 이 보호가
  사라지므로, 바꾸기 전에 같은 시험을 다시 하세요.
- **전화·우편 수신동의는 명시적으로 `false` 를 보냅니다.** 도너스는 이 칸들을 안 보내면
  전부 `true` 로 둡니다. 폼에 "광고 전화는 하지 않습니다" 라고 적어 놓고 동의로
  넣으면 거짓말이 됩니다.
- ⚠️ **참여자 수(`✊ N명이 함께하고 있습니다`)는 도너스에서 못 읽습니다.** Forms API 는
  쓰기 전용이고, 집계를 읽으려면 API Key 가 필요한데 그 키는 브라우저에 두면 안 됩니다.
  그래서 `'donus'` 에서는 집계를 부르지 않고 숫자 줄을 비웁니다(0 명처럼 보이지 않게).
  숫자를 다시 띄우려면 어디선가 집계본을 받아 `joinCounts` 에 넣어 주면 됩니다.

**하드코딩돼 있던 `/api/report` · `/api/join` · `/api/regions` 를 모두 걷어냈습니다.**
2026-08-24 운영 구조 변경(`OPERATIONS.md`)으로 그 주소들은 쓰지 않습니다 — 부르면
실패하거나 아무 데도 저장되지 않았습니다. 이제 주소는 `DOK_INTAKE` 한 곳에만 있습니다.

### 후원으로 보내는 곳 — `DOK_DONATE` (2026-09-03)

주소를 **한 곳에서** 정합니다. 따라다니는 후원 바와 **서명 완료 화면**이 같이 씁니다.

```js
const DOK_DONATE = {
  url:   '',                  // 도너스 온라인모금 > 모금함 주소. 비면 action.or.kr
  label: '후원으로 힘 보태기',  // 금액을 정한 모금함이면 '1,000원으로 힘 보태기' 처럼
};
```

**서명을 마친 화면에 후원 권유를 답니다.** 서명 앞에 결제를 두지 않은 것은 의도입니다 —
문 앞에서 돈을 받으면 서명하는 사람 수가 크게 떨어지고, 밑빠진 독상은 "몇 명이
분노했는가" 를 보여주는 캠페인이라 그 숫자가 죽으면 캠페인이 약해집니다.
방금 이름을 더한 사람이 가장 마음이 열려 있는 순간이라 거기에 두었습니다.

클릭은 `donate_click` 으로 세되 `from: 'join_done' | 'bar'` 로 갈라 기록합니다.
어느 쪽이 실제로 후원으로 이어지는지 보려는 것입니다(GA4 ID 를 넣어야 쌓입니다).

## 서명한 사람은 도너스 어디에서 보나

**`서비스 > 활동기록`** 입니다. 구성원 목록(`모금 > 구성원`)과는 별개 화면이라
후원자 명부와 섞이지 않습니다.

- 탭 **`참여`** 를 누르면 활동유형 `ENG` 만 모입니다. 서명은 전부 `ENG` 로 보냅니다.
- **`+상세검색` → 활동채널 `밑빠진독상(미래대응기금)`(AC008)** 으로 좁히면
  밑빠진 독상 서명만 나옵니다. 사업별로 더 쪼개려면 태그(사업 id)로 거르세요.
- 오른쪽 아래 **`출력`** 으로 엑셀로 뽑습니다.

**구성원 목록에서는 갈라낼 수 없습니다.** `전체/개인/단체` 탭은 도너스가 고정한
것이고, Forms API 로는 구성원분류·그룹을 지정할 수 없습니다(쓸 수 있는 것은 이름·
이메일·휴대폰·메모·수신동의·사용자정의필드뿐). 게다가 `updateOnMatch:false` 라
**이미 있는 사람이 서명하면 구성원 정보를 아무것도 안 건드립니다.**
그래서 사람이 아니라 **행위(활동기록)** 를 기준으로 가릅니다.

섞이는 것이 손해만은 아닙니다. 서명만 한 사람이 나중에 후원회원이 되면 같은 구성원으로
이어져서 "서명하고 후원까지 간 사람" 을 셀 수 있습니다. 명부를 갈라 두면 그것을 잃습니다.
